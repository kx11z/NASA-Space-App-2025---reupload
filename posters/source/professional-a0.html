01 Research problem and contribution

Transit surveys produce large time-series datasets, but a brightness dip alone does not confirm a planet. Stellar variability, eclipsing binaries, instrumental noise and processing artifacts can create similar signatures. ExoPlain combines a candidate-data interface, FITS processing, experimental classifiers and a language-model explanation layer so learners can trace how an input becomes an assessment.

Research question: How can an interactive AI system make exoplanet candidate evidence easier to interpret while preserving uncertainty and the distinction between screening and scientific confirmation?

02 End-to-end analysis pipeline

1 · AcquireUpload a TESS/Kepler-style FITS light curve or manually enter 16 orbital, transit, stellar and sky-position fields.
2 · CleanSelect TIME and flux columns, remove NaN/Inf rows, require at least 100 valid samples and normalize flux by its median.
3 · RepresentLinearly resample to 2,048 points. Compute 37 statistical, transit, spectral, rolling, trend and autocorrelation features.
4 · ClassifyScale the feature vector and obtain Random Forest probability. CNN, LSTM and MLP scripts explore sequence-model alternatives.
5 · ExplainConvert candidate fields or labeled features into a constrained Gemini prompt and return a readable assessment with key evidence.
Two software paths currently coexist: manual parameter entry calls Gemini directly, while FITS upload calls the Python feature service and Random Forest path. The production goal is one auditable pipeline in which the classifier supplies evidence and the LLM explains it.

03 Data preparation and modeling methods

A · Labels and dataset

Training scripts use TESS light curves and TFOPWG dispositions. The code maps CP/KP/PC to the positive class and FP/Unknown to the negative class. Project documentation reports 7,638 curves with strong class imbalance, so label provenance and candidate-level grouping must be audited before publication.

y = 1 for CP/KP/PC; y = 0 for FP/Unknown

B · Signal preprocessing

The FITS service searches common time and flux columns, removes invalid samples, median-normalizes the flux and interpolates every curve to a fixed 2,048-point representation. Training augmentation adds small Gaussian noise, amplitude scaling and vertical shifts.

f_norm(t) = f(t) / median(f); x ∈ R²⁰⁴⁸

C · Feature-based classifier

The Random Forest path standardizes 37 engineered features and uses a stratified 80/20 split with class-balanced trees. Features cover distribution shape, counts beyond 1σ-3σ, proxy transit depths, frequency-band power, trend fit and autocorrelation. The saved model stores feature importance and AUC metadata.

p_planet = RF(StandardScaler(φ(x))); threshold = 0.50

D · Sequence-model experiments

The 1D CNN stacks five convolution blocks (64→128→256→512→512 channels), batch normalization, pooling and dropout before a 512→256→128→64→1 head. A compact LSTM downsamples 2,048 to 256 timesteps, uses 32 hidden units and a 64→32→1 head. An MLP provides a dense baseline.

Loss: BCEWithLogits · Adam lr=10⁻³ · weight decay=10⁻⁴

E · Training controls

  • Random seed 42 and 80/20 train-validation split.
  • ReduceLROnPlateau halves learning rate after stalled validation loss.
  • Early stopping and gradient clipping limit unstable training.
  • Dropout and augmentation reduce memorization risk.

F · Transit physics represented

Candidate inputs include orbital period, epoch, impact parameter, transit duration and depth, planet radius, equilibrium temperature, insolation, SNR, stellar temperature, surface gravity, stellar radius, magnitude and sky position.

Transit depth δ ≈ (Rₚ / R★)²

05 Explainability design

Evidence selectionFor manual entry, the prompt contains all submitted measurements. For FITS, the service emits labeled engineered features and Random Forest probability.
Structured generationThe API asks Gemini for a Boolean assessment and five important features with High/Medium/Low relevance descriptions.
Human-readable resultThe interface translates model evidence into plain language so users can connect the classification to transit depth, periodicity, stellar context and data quality.
Intended roleThe explanation supports learning and candidate triage. It does not replace follow-up observation, vetting reports or expert confirmation.
Known implementation gap: the manual Gemini route currently maps answers to fixed 85%/15% confidence and defaults missing answers toward “true.” The upload route can return randomized fallback features if the Python service fails. Both behaviors must be removed or visibly labeled before scientific use.

07 Validation plan and next technical milestones

1 · Dataset auditRecord TIC identifiers, sectors, label source and download date. Resolve Unknown labels and quantify duplicates.
2 · Leakage-safe splitGroup observations by target star before splitting so repeat sectors from one object cannot enter both train and test.
3 · Baselines and ablationsCompare RF, CNN, LSTM and MLP against class-frequency and simple depth/period rules. Remove feature families one at a time.
4 · CalibrationReport reliability curves, Brier score and threshold tradeoffs. Replace fixed confidence with measured probabilities.
5 · External validationTest on a later TESS sector or a separately curated candidate set, preserving untouched labels until final evaluation.
6 · Explanation studyMeasure whether students can identify the decisive features, uncertainty and need for follow-up more accurately after using ExoPlain.
Required reporting: sample counts by class · target-grouped train/validation/test split · ROC-AUC and PR-AUC · precision, recall and F1 · confusion matrix · calibration error and Brier score · inference latency · failure-mode examples.
Failure modes that the evaluation must isolate
Eclipsing binariesDeep V-shaped or alternating events can mimic planetary transits.
Stellar variabilitySpots, pulsations and flares change brightness without an orbiting planet.
Instrument artifactsMomentum dumps, gaps and background changes can create false structure.
Low-SNR transitsShallow events test sensitivity, calibration and threshold stability.
Distribution shiftDifferent sectors, cadences and stellar populations may alter model behavior.
Missing metadataIncomplete stellar context can weaken both classification and explanation.
Decision rule for the final system: label outputs as candidate-screening evidence, publish calibrated probability with uncertainty, expose whether the result came from the classifier or an unavailable-service fallback, and require human review before any confirmation claim.
Take-home message
ExoPlain connects raw exoplanet evidence, machine-learning predictions and readable explanations in one learning workflow. The next priority is rigorous validation, calibrated uncertainty and removal of simulated fallbacks.
